# Protected native plumbing: execution qualification

26 September 2026. [Registration](PROTECTED_NATIVE_PLUMBING_PROTOCOL.md) ·
[Integrated cell](PROTECTED_CELL_RESULTS.md) · [Index](README.md)

## Assessment

The source-bound adapter, isolated worker and parent supervisor are implemented.
Qualification is **in progress**, not a new field experiment. All eight synthetic
cases traverse a real subprocess, the complete synthetic cell, saved-graph audit
and parent acknowledgement. Their arrays are deliberately nonphysical.

The existing controller, numerical code, acceptance limits, historical sources
and evidence remain unchanged. Full committed-source regression and the actual
eight-context source preflight are still pending. No native model, producer
certificate, equilibrium calculation or new coil search has run in this stage.

## Interfaces

- `protected_native_inputs.sources` preserves the predecessor graph and the
  completed synthetic qualification, and binds eleven new code/test files.
  `build_context` reconstructs the eight original contexts using the old checked
  NPZ reader for historical archives.
- `NativeAdapter` explicitly connects the original native factory/executor to
  the qualified cell. Tests replace those lazy bridges with stubs. It verifies
  original-seed construction, method, physical coordinates, target normalization,
  effective cache invalidation and complete returned numerical bundles.
- `protected_worker_control` bounds canonical atomic pipe messages and the
  600-second search / 1,800-second cell clocks. The exact endpoints fail. Journal
  proxies preserve payloads and signal search entry before record persistence.
- `run_protected_cell_worker.run_worker` requires explicit dependencies and
  checks four single-thread environment variables before scientific imports and
  at cooperative boundaries. It binds the sources before and after execution.
  There is intentionally no native command-line launch yet.
- `protected_process.supervise_cell` owns a new POSIX process group, independent
  deadline/disk polling, bounded cleanup and completion acknowledgement. It never
  treats a discovered result file as a successful return.

Only a successfully returned parent acknowledgement reference acknowledges the
execution. All software reports retain false physical-admission and Step 4 flags.
This is a trusted, single-writer local workflow, not an untrusted-PR sandbox.
Parent identity is checked cooperatively; there is no hard kill-on-parent-death
guarantee. Parent callbacks are trusted synchronous functions, not independently
preempted operations. Thread-environment checks do not measure runtime thread pools.

## Checks and retained failures

- Control: 46 tests pass. Review retained a 43-pass/three-failure run for exact
  deadline endpoints and a regular file masquerading as a pipe; fixed by `>=`
  deadline rejection and explicit FIFO descriptor validation.
- Worker: 26 tests pass. Independent review reproduced thread-setting drift that
  still produced an envelope claiming the original settings. Retained red run:
  22 pass/four fail. Recheck actual environment at every cooperative resource
  boundary and record observed values; all four mutations are now rejected.
- Source/adapter: 131 tests pass after adding the pipeline source pin. Retained
  red run: 122 pass/seven fail for forwarded callbacks after swallowed failure
  and coercible normalization scalars. The adapter now stays poisoned and checks
  scalar types before conversion. No native calls were made by these tests.
- End-to-end pipeline: 11 tests pass (11.72 s): eight registered cases and source
  drift, thread drift and nonzero exit after a worker return. The latter leaves
  complete result files but never a parent acknowledgement.
- Parent-supervision review and final integrated/source-frozen qualification are
  still in progress. Development JUnit files remain under
  `artifacts/protected-native-plumbing-v1/`; failed attempts are retained.

The implementation roles are `protected_runner_map` (source/adapter),
`protected_budget_impl` (parent supervision) and maintainer (control/worker/pipeline),
with independently authored internal review by `cell_integration_review`.
These are internal checks, not external peer review or independent hardware tests.
