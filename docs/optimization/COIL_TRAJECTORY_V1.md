# Existing coil-trajectory export, version 1

Historical runs retain this format. New fitter runs use
[prospective recording and export v2](COIL_TRAJECTORY_V2.md); the same exporter
selects the format from recorded version metadata.

Question: can existing fitter files supply reproducible records before joint
optimization comparisons, without another recorder? The read-only
[exporter](../../scripts/export_coil_trajectory.py) uses Python's standard library.
It does not evaluate fields, run submitted code or fetch artifact URLs.

```bash
python scripts/export_coil_trajectory.py --run results/my-fit \
  --output results/my-trajectory.jsonl --max-mib 64
```

Use a closed run with `seed.json`, `inputs.json` and `trial-*.json` files.
`search.json` and `result.json` are optional; absence is recorded. Add
`--artifact-base <immutable-run-URI>` for obtainable artifact references. Without
it, artifact URIs are null: hashes alone do not establish availability. Keep the
original run, archive manifest, licenses and attribution alongside the export.

## Schema: `fusion-coil-trajectory-v1`

Each UTF-8 JSONL line has `format` and `type`. Canonical JSON gives deterministic
bytes. Only six base coils, order 5 or 8, nfp=2 are supported.

- **`run`:** content-derived run/trajectory identity; parent seed hash; canonical
  coefficient names and metre units; seed physical-copy/current mapping;
  Cartesian axes and unit-period Fourier parameter; target identity, signed flux
  (Wb) and B² normalization (T²); recorded producer commit/dirty state, environment,
  source hashes, solver options and budgets. Original machine paths become opaque
  path hashes and basename labels, not public artifact locations.
- **`evaluation`:** numeric index, candidate identity bound to seed conventions,
  coordinates, target and recorded current scale; role, coefficients, full
  gradient, objective and unmodified metrics; retained error/rejection value;
  selected-candidate flag. `evaluation_status` is `completed`, `failed` or
  `incomplete` (attempt without terminal file). All trial indices are retained.
- **`verification`:** optional final report fields, resolutions and source hashes,
  linked to the selected index. Fine/interior/geometry results remain separate
  from search metrics. The recorded result is not independently revalidated.
- **`export_complete`:** counts and input-file hashes/optional artifact URIs.
  A file without this final line is incomplete. Export completion is software
  completion, not numerical agreement or physical acceptance.

`null` means absent, never zero. Task IDs, constraints/objective weights, search
resolution and per-trial elapsed cost are unknown where the original recorder
did not capture them. Known metric units are listed; unlisted units are unknown.
The objective/gradient retain producer semantics, with no invented dimensional
unit or reweighting. Raw constraint flags remain metrics, not acceptance labels.

`solver_step_status` is always `unknown`: completed evaluations, probes and
numerically rejected trials are not accepted optimizer iterates. Selection is
the fitter's completed eligible candidate, not solver convergence. No plasma
coefficient trajectory is implied by this fixed-target coil format. Physical
acceptance is never inferred from search, selection or export success.

## Controls, retention and limits

```bash
PYTHONPATH=src python -m pytest -q tests/test_coil_trajectory.py
```

The tiny synthetic example generated by these tests includes completed, failed
and attempt-only records, plus separate fine verification. Controls check named
ordering, order 8, missing metrics, selection identity, unchanged inputs and
failure-preserving publication. The exporter rejects inconsistent records and
symlinks, never overwrites output, and retains `.partial` on failure. Its default
output cap is 64 MiB (maximum 256 MiB); inputs remain under the existing strict
2 MiB/file JSON limit. No source files or heavy field arrays are copied. Identical
artifact bytes keep the same hashes; counts are not independent design coverage.

This is a scoped prerequisite for [#38](https://github.com/DrWorkhard/nuclear-fusion-at-home/issues/38),
not its full completion. The [v2 hook](COIL_TRAJECTORY_V2.md) supplies settings,
costs, accepted iterates and a fixed-target replay for new runs. Plasma variables
and future joint comparison fidelity remain separate work. Original native
environments, raw evidence and acceptance checks are unchanged.
